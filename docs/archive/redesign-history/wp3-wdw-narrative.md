## Editorial rules

- Use “persistent computational environment,” not “dashboard,” “agent team,” or “character simulation.”
- Say “tested reference seam” only for behavior covered by the public tests.
- Keep “public architecture,” “fixture proof,” “experimental,” and “planned” visually and verbally distinct.
- Describe residents as bounded participants that may read, interpret, propose, abstain, and act only within explicit capability grants.
- Describe World View as a freshness-aware, viewer-authorized projection surface. It is not the source of truth.
- Describe Bridget as an independent experimental integration and The Human Model as a domain system that retains ownership of its evidence.
- Never imply that production storage, live connectors, a live World View adapter, autonomous residents, or a public deployment exists.

## Reading rhythm

The first screen answers “what is this?” The next two sections answer “why does it exist?” and “how is it shaped?” Evidence follows before named residents, so the names cannot be mistaken for proof of autonomous behavior. Limitations precede technical links, leaving the reader with an honest boundary and an optional path deeper.
